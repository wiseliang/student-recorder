# 拍照启动优化 v1.14.1

拍照/相册是本机操作，不再等待完整的识人范围请求；名单、授权和库的检查继续由服务端在查询时执行。慢网及识人范围读取失败不再阻止先拍照。范围刷新独立显示状态，不占用拍照锁。

已授予相机权限时不再重复申请。首次未授权才申请，被永久拒绝时提示到系统设置。SDK 52 expo-image-picker 16.0.6 的原生 launchCameraAsync 内部也会重复 askForPermissions，因此构建时同步修复原生层：若相机及旧Android所需存储权限均已授予，直接继续，不再启动权限请求。仍然遵循Android权限检查，不绕过首次授权。

相关上游记录：https://github.com/expo/expo/issues/39480 。该记录描述部分Android16设备的重复权限回调挂起，不能据此断定用户手机一定属于该问题。未收到用户具体机型/系统与耗时前，不给出实机提速倍数承诺。

构建修复 scripts/patch-camera-permissions.cjs 仅支持锁定的16.0.6，源代码不符合预期时阻止构建，防止依赖升级后误套补丁。android/build.gradle显式执行，因此npm ci --ignore-scripts不会漏掉修复；脚本可重复运行。

增加打开相机、读取照片的即时状态，避免看起来没反应；重复点击只启动一次。小于等于1600px照片直接预览，查询时再统一转JPEG，减少拍照返回后的重复处理。大照片仍先缩小，避免预览占用过多内存。

回归包括已授权不重新申请、首次/拒绝/永久拒绝、相册取消与无效结果、慢网未完成时真实页面仍可调用相机、快速重复点击去重，以及原生补丁幂等和版本保护。原有裁剪、上传、账户隔离与教务恢复回归保留。手机系统相机实际启动耗时仍需在用户真机验证。
